As an outdoor enthusiast, I want to view a detailed breakdown of conditions at a specific location so that I can understand why a location is scored a certain way, read AI-generated analysis, and find the best hour to go.

## Requirements

- Display a sticky header with back button (ChevronLeft) and location name. Back button navigates to the previous page.
- Show a large circular score display (0-100) with background color from the condition theme (condition-ideal, condition-acceptable, condition-marginal, condition-unsuitable). Display condition badge pill below the score and "Best conditions at {time}" subtitle showing which hour achieves the peak score.
- Render a vertical stack of factor breakdown cards under a "Conditions" heading. Each card has: icon in colored rounded container, factor name heading, data grid with labeled values, and AI interpretation paragraph in muted background. Render a factor card for each non-null condition field in the forecast entry (e.g. wind, tide, water, temp, precipitation, uv, humidity, visibility, daylight). The server controls which factors are relevant per activity.
- Factor cards with non-ideal conditions show a colored border (orange for warning, red for danger) and a condition badge pill (e.g. "Warning", "Gusty", "Danger") aligned right in the header.
- Display AI analysis section with multi-paragraph explanation in a card. Background uses a subtle tint of the condition theme color (e.g. `color-mix(in srgb, var(--condition-ideal) 10%, var(--background))`). Analysis text comes from the forecast `analysis` field, split by `\n\n` into paragraphs.
- Render a horizontally scrollable forecast strip showing hourly scores from the `hourly` array. Each time slot shows hour label, score number (colored by condition), and condition bar. The best hour has a star badge. Tapping a time slot is a future interaction (read-only for now).
- Show a Share Location button at the bottom (outline style, primary color) that triggers `navigator.share()` with current URL and location name, falling back to clipboard copy. When the condition is "unsuitable", show a disabled "Not Recommended Today" button with helper text explaining sharing is disabled for safety.
- On tablet (md breakpoint), factor cards display in a 2-column grid. Score circle and text scale up slightly. Padding increases.
- The location detail page reads forecast data from the existing forecast store via `useForecastStore`. The geolocation route param (lat,lng) combined with the selected activity, date, and time range forms the forecast key to look up the entry.
- The location detail page is a single async server component at `/location/[name]/[geolocation]/page.js` with `generateMetadata` using `deslugify(name)` for SEO. Uses `getForecastsByLocations([[lat, lng]])` to fetch data and wraps `LocationDetail` in `ForecastStoreProvider` with `initialState`, following the `[city]/home/page.jsx` pattern. Both `/home` and `/[city]/home` link to this single route.
- All visible text is localised via i18next under a new `locationDetail` namespace.
